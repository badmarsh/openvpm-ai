# 💾 7. Detailný manuál zálohovania a obnovy (Postgres, S3)

Tento prevádzkový runbook popisuje technické postupy zálohovania, obnovy databázy a manažmentu binárnych medicínskych príloh pre inžinierov a správcov systému OpenVPM AI (`docs/backup-restore-runbook.md`).


---

## 1. Architektúra zálohovania

Zálohovanie prebieha na dvoch nezávislých úrovniach:


1. **Kontinuálna databázová archivácia (PITR — Point-in-Time Recovery):**
   * Zabezpečuje možnosť vrátiť stav databázy do ľubovoľnej sekundy za posledných 30 dní.
   * Dosahovaný parameter **RPO < 15 minút**.
2. **Denný štruktúrovaný snapshot praxe (JSON Export):**
   * Spúšťa sa každú noc o 03:00 UTC cez `/api/cron/backup`.
   * Každá prax má vlastný export uložený v ceste `backups/{practiceId}/{YYYY-MM-DD}.json`.
   * Beží v izolovanej read-only transakcii `REPEATABLE READ` pre zaručenie konzistentnosti.
   * Heslá a citlivé kľúče sú pri exporte automaticky sanitizované.


---

## 2. Manuálne zálohovanie cez terminál (PostgreSQL)

Pre lokálne inštalácie alebo mimoriadne zálohy pred veľkými aktualizáciami:

```bash
# 1. Export celej databázy vrátane RLS schémy
docker exec -t openvpm-postgres-1 pg_dump -U openpims -d openvpm_ai -Fc > backup_$(date +%F_%H%M%S).dump

# 2. Rýchly textový SQL dump vybranej kliniky
docker exec -t openvpm-postgres-1 pg_dump -U openpims -d openvpm_ai --data-only --table="soap_notes" > soap_backup.sql
```


---

## 3. Postup obnovy databázy (Disaster Recovery Restore)

Pri havárii servera postupujte nasledovne:


1. **Príprava cieľovej databázy:**

   ```bash
   docker exec -i openvpm-postgres-1 dropdb -U postgres openvpm_ai --if-exists
   docker exec -i openvpm-postgres-1 createdb -U postgres openvpm_ai
   ```
2. **Obnova zo záložného dump súboru:**

   ```bash
   docker exec -i openvpm-postgres-1 pg_restore -U postgres -d openvpm_ai -v backup_file.dump
   ```
3. **Znovunačítanie RLS politík a servisu:**

   ```bash
   OPENPIMS_APP_DB_PASSWORD='<heslo>' pnpm db:rls
   OPENPIMS_APP_DB_PASSWORD='<heslo>' pnpm db:rls:test
   ```
4. **Spustenie integrity checku:**

   ```bash
   bash scripts/dr-restore-drill.sh
   ```


---

## 4. Zálohovanie a obnova medicínskych snímok (MinIO / S3)

Medicínske snímky (RTG, CT, sono) sú uložené oddelene v objektovom úložisku:

* S3 bucket má zapnuté verziovanie objektov (*Object Versioning*) a ochranu proti prepísaniu (*Object Lock*).
* Zrkadlenie lokálneho MinIO úložiska do off-site cloudu zabezpečuje utilita `rclone` alebo `mc mirror`:

  ```bash
  mc mirror --watch /data/minio/openpims-files remote-s3:openpims-backup/
  ```
