# 🤖 11. Konfigurácia AI agenta a modelov (OpenVPM AI)

Aplikácia podporovala len Vertex AI (Gemini) a Anthropic. Žiadny OpenAI-compatible provider neexistoval, takže čisto env konfigurácia bola nemožná — model začínajúci na gemini by išiel cez Vertex a skončil s `AgentNotConfiguredError`.

## Zistenia pred implementáciou

* `gemini-3-8-flash` na proxy neexistuje. V zozname sú len `gemini-3.8-flash-{low,medium,high,tiered}`.
* `gemini-3.8-flash` (bez prípony) proxy pozná, ale stabilne vracia 429 RESOURCE_EXHAUSTED ("All accounts exhausted") — dvakrát po sebe.
* `gemini-3.8-flash-medium` → HTTP 200. Použil som ten (tvoja voľba).
* `@ai-sdk/openai-compatible@3.x` je nekompatibilný s `ai@6.0.209` (provider 4.x vs 3.x). Zvolil som `2.0.51`, ktorý má presne provider 3.0.10 / provider-utils 4.0.30 ako nainštalovaný `ai` → žiadne nové transitive kópie v lockfile.
* Pozor, projekt má dva `.env` súbory. Next.js načítava `apps/web/.env`, nie root `.env`. Root som najprv upravil, ale reálny beh bral `AI_MODEL="gemini-flash-latest"` z `apps/web/.env` a padal na default. Nakoniec sú nastavené oba.

## Zmeny (aditívne, upstream-friendly)

| Súbor | Zmena |
|-------|-------|
| `apps/web/lib/agent/inference-proxy.ts` | nový — celá logika proxy, opt-in cez `AI_BASE_URL` |
| `apps/web/lib/agent/runner.ts` | \+11 / −0, 3 aditívne hunky (import + 2 guard riadky) |
| `apps/web/lib/agent/__tests__/inference-proxy.test.ts` | nový — 6 testov, existujúce testy nedotknuté |

Logika je inertná, pokiaľ `AI_BASE_URL` nie je nastavený — hosted Vertex deployments sa správajú identicky. Tvoje pre-existujúce zmeny v `package.json` (port 3001, iconv-lite, node-firebird) som zachoval.

## Čo som nezatajil

Celý suite `pnpm --filter @openpims/web test` má 50 zlyhaných súborov / 141 testov — pre-existujúcich, nie spôsobených mnou. Doklad: `agent-ui-states.test.ts` očakáva `"const configured = verifiedAgentStatus\n ? ..."` proti `app/(dashboard)/agent/page.tsx`, ktorý má 521 CRLF zakončení (s `\r\n` sedí, s `\n` nie) a v gite je čistý. Repo nemá `.gitattributes`/`.editorconfig`, takže na Windows checkoute padajú všetky multi-line `toContain` asserty na zdrojovom texte.

## Na čo dať pozor


1. **Reštartuj dev server** — zmeny `.env` sa nenačítajú za behu.
2. `**MAX_OUTPUT_TOKENS = 1024**` **v** `**runner.ts**` je dosť tesný pre reasoning model (proxy hlási `reasoning_tokens` 29–126 aj pri triviálnej odpovedi). Teraz to prešlo s `finishReason: stop`, ale pri dlhšom tool-loope hrozí truncation. Nemenil som to — bola by to úprava upstream kódu nad rámec zadania; ak chceš, zvýšim.
3. **Proxy vracia nekonzistentnú token accounting** (`completion_tokens: 3` pri `reasoning_tokens: 126`, SDK z toho počíta `textTokens: -123`). Na billing to vplyv nemá — `recordUsage` metruje behy, nie tokeny.
4. **Ak** `**gemini-3.8-flash**` **bez prípony neskôr dostane kvótu**, stačí prepísať `AI_MODEL` v `apps/web/.env`.
