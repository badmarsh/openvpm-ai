# 🔌 6. Rozhrania REST API a tRPC procedúry pre integrácie

Tento dokument poskytuje technickú špecifikáciu rozhraní API pre externé integrácie s informačným systémom **OpenVPM AI** (napr. prepojenie s účtovným softvérom, laboratóriami, e-shopom alebo mobilnými terminálmi).


---

## 1. Dvojvrstvová architektúra rozhraní API

Systém disponuje dvoma hlavnými typmi programových rozhraní:


1. **tRPC procedúry (**`**/api/trpc**`**):**
   * Určené pre internú komunikáciu medzi klientskym webovým rozhraním (Next.js) a serverom.
   * Poskytujú end-to-end typovú bezpečnosť cez TypeScript a schémy Zod.
   * Všetky požiadavky overujú kontext prihláseného používateľa a tenant scope `ctx.practiceId`.
2. **Verejné REST API v1 (**`**/api/v1**`**):**
   * Štandardizované JSON rozhranie určené pre externé softvéry tretích strán.
   * Využíva HTTP metódy (GET, POST, PUT, DELETE) so stavovými kódmi HTTP.


---

## 2. Autentifikácia a autorizácia externých volaní

Každé volanie na REST API vyžaduje autorizačnú hlavičku s privátnym API kľúčom praxe:

```http
Authorization: Bearer op_sec_xxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json
```

* **Generovanie kľúčov:** Správca praxe generuje kľúče v `Nastavenia → API kľúče`.
* **Rozsah oprávnení (Scopes):** Kľúč má explicitne definovaný rozsah (napr. `patients:read`, `invoices:read`, `appointments:write`).
* **Tenant scoping:** API kľúč je kryptograficky viazaný výhradne na jednu konkrétnu ambulanciu a nedokáže pristúpiť k dátam inej kliniky.


---

## 3. Prehľad kľúčových REST API endpointov

| Metóda | Endpoint | Popis | Oprávnenie (Scope) |
|--------|----------|-------|--------------------|
| `GET`  | `/api/v1/patients` | Zoznam pacientov kliniky s možnosťou filtrovania podľa mena, druhu alebo mikročipu. | `patients:read`    |
| `GET`  | `/api/v1/patients/:id` | Detail zdravotnej karty pacienta vrátane vakcinácií a hmotnosti. | `patients:read`    |
| `GET`  | `/api/v1/clients` | Zoznam registrovaných majiteľov zvierat a ich kontaktných údajov. | `clients:read`     |
| `GET`  | `/api/v1/appointments` | Harmonogram návštev a rezervácie na zvolený deň. | `appointments:read` |
| `POST` | `/api/v1/appointments` | Vytvorenie novej rezervácie (napr. z externého webu kliniky). | `appointments:write` |
| `GET`  | `/api/v1/invoices` | Export faktúr a položiek za účtovné obdobie pre programy POHODA, OMEGA alebo KROS. | `invoices:read`    |
| `GET`  | `/api/v1/inventory` | Aktuálny stav zásob liečiv a materiálu na sklade. | `inventory:read`   |
| `GET`  | `/api/health` | Monitorovací liveness & readiness healthcheck servera. | Verejné            |


---

## 4. Limity volaní (Rate Limiting) a bezpečnosť

* **Frekvenčný limit:** Predvolený limit je **120 požiadaviek za minútu** na jeden API kľúč. Pri prekročení server vracia kód `429 Too Many Requests`.
* **Auditný log:** Každé volanie API s modifikáciou dát je zaznamenané v systémovom bezpečnostnom audite s IP adresou a časovou pečiatkou.
