## 1. Executive Summary

This report documents the security, audit-integrity, concurrency hardening, and pilot readiness improvements completed during the 9.3 Correctness Closure Sprint.

The repository was systematically audited across its real write paths, agent tools, confirmation workflows, and audit ledgers. All identified vulnerabilities and concurrency gaps were resolved, strictly conforming to the project skills contract:
- Zero vanilla table schema changes (all extensions in `packages/db/schema/ext_*`).
- Fail-closed role authorization everywhere.
- AI remains strictly assistive (never autonomous; zero finalizations or prescriptions without attending clinician confirmation).
- Strict i18n symmetry (Slovak primary).
- Honest status labeling across all documentation (`IMPLEMENTED_AND_TESTED`, `DEPLOYMENT_REQUIREMENT`, `PILOT_TARGET`, `LEGAL_REVIEW_REQUIRED`, `NOT_IMPLEMENTED`).

## 4. What Is Now Proven by Code and Automated Tests

### 4.1 Authorization Boundary (`authorization.test.ts` — 35 tests)
- Proves `assertAgentRole()` denies: undefined, null, empty, whitespace, SQL injection, JSON injection, unknown roles (`superuser`, `portal_user`, `service_cron`), and unauthorized roles.
- Proves all 26 agent tools reject `userRole: undefined` and `userRole: "viewer"`.
- Proves privileged tools (`create_prescription`, `get_controlled_substances_log`, `audit_missed_charges`, `generate_rvps_report`, `check_withdrawal_periods`, `check_rabies_observations`) strictly reject `front_desk` and `technician`.
- Proves clinical tools strictly reject `front_desk`.

### 4.2 Audit Ledger & Advisory Locking (`audit-ledger.test.ts` — 15 tests)
- Proves `appendAiAuditEvent` acquires transaction-scoped advisory locks on practice ID.
- Proves strictly monotonic sequence allocation (`sequenceNumber: 1` genesis, incrementing +1 per event).
- Proves cryptographic linking of `previousEventHash` to prior record's `eventHash`.
- Proves deterministic canonical SHA-256 payload generation.
- Proves automatic clinician edit detection (`wasEditedByClinician: true` when draft and confirmed hashes diverge).
- Proves fail-closed detection of unsequenced legacy rows (`CHAIN_BROKEN`).

### 4.3 Replay-Safe Confirmation Envelopes (`clinician-confirmation.test.ts` — 15 tests)
- Proves issuing 15-minute expiring confirmation envelopes.
- Proves atomic single-use consumption (`PENDING` → `CONSUMED`).
- Proves replay rejection (`ALREADY_CONSUMED`).
- Proves expiry rejection (`EXPIRED`).
- Proves tampering rejection across actor, role, practice, action, entity, revision, draft hash, and payload hash.

### 4.4 Extension AI Finalization Integration (`extensions-ai-finalization.integration.test.ts` — 11 tests)
- Proves imaging confirmation rejects unprivileged roles, rejects already-completed analyses, rejects concurrent revision mismatch, and appends audit event atomically.
- Proves voice SOAP finalization rejects unprivileged roles, rejects already-finalized dictations, rejects concurrent revision mismatch, and links `soapNoteId` within transaction.
- Proves discharge report saving rejects unprivileged roles when finalizing, rejects mutations to finalized reports, and rejects concurrent revision mismatch.

### 4.5 Synthetic End-to-End Pilot Flow (`pilot-e2e-flow.integration.test.ts` — 8 tests)
- Proves deterministic multi-step lifecycle:
  1. Receptionist lookups allowed.
  2. Receptionist prescription creation blocked (`FORBIDDEN`).
  3. Vet issues confirmation envelope for AI SOAP draft.
  4. Vet finalizes SOAP note; confirmation consumed and logged as sequence 1.
  5. Replay attack on consumed token rejected (`ALREADY_CONSUMED`).
  6. Vet creates prescription (authorized role).
  7. Vet finalizes discharge report; logged as sequence 2.
  8. Verifies cryptographic continuity of the entire multi-step audit ledger.

## 7. Residual Risks

1. **Database Administrator Hash Tampering:** A DBA with direct SQL write access and knowledge of the hashing algorithm could alter records and recompute hashes. Mitigation: External WORM anchoring (S3 Object Lock / RFC 3161) scheduled as `PILOT_TARGET`.
2. **Pre-Migration Unsequenced Rows:** If existing pilot databases contain audit rows without `sequenceNumber`, `appendAiAuditEvent` throws `CHAIN_BROKEN`. Mitigation: Run `scripts/verify-ai-audit-trail.ts` before appending.
3. **E2E Browser Automation:** Playwright UI test suite for real browsers is documented and targeted for post-pilot hardening; server-level integration tests currently cover the complete operational flow.
