## Findings

### BH-001 -- vitest config missing NODE_ENV=test; all data-import tests fail without it
- Severity: Medium
- Vector: 2.11 (Test-suite trustworthiness)
- Status: NEW
- Location: `apps/web/vitest.config.ts:L1-L14` + `apps/web/server/routers/data.ts:L361-367`
- Evidence: [PROVEN: `cross-env NODE_ENV=test npx vitest run` -> 0 failures; raw `npx vitest run` -> 33 failures]
- Root cause: `legacyImportCompatibilityOpen()` checks `process.env.NODE_ENV === "test"` to grant legacy import compatibility. The vitest config does not set `NODE_ENV` to `"test"`, so the fallback `now < LEGACY_IMPORT_COMPATIBILITY_END_MS` (2026-08-15) always fails -- the cutoff date passed 30 days ago. All 33 data import tests that rely on legacy compatibility throw "This import session is out of date."
- Reproduction: `cd apps/web && npx vitest run server/__tests__/data-import-dedup.test.ts` -> 20+ failures. Add `NODE_ENV=test` -> 0 failures.
- Suggested fix: Add `env: { NODE_ENV: "test" }` to `vitest.config.ts` `test` block.
- Confidence: High
