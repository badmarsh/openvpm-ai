## 1. PDF parser stabilita + unit test `extractPdfText`

**Zistenie:** Stredná. `pdfjs-dist` nebola deklarovaná v `apps/web/package.json`
(phantom dependency — len tranzitívna cez `pdf-parse@2.4.5`), import
`pdfjs-dist/legacy/build/pdf.mjs` z `apps/web` sa v Node nepodarilo
vyrešoviť (`require.resolve` zlyhá), a `Dockerfile:45` copy-uje worker cez
verziou uzamknutú cestu `.pnpm/pdfjs-dist@5.4.296/...` — akokoľvek sa
pdfjs-dist bumpne, build sa zlomí.

**Dôkaz:** `pnpm why pdfjs-dist` (len cez pdf-parse),
`node -e "require.resolve('pdfjs-dist/legacy/build/pdf.mjs')"` z `apps/web`
→ `MODULE_NOT_FOUND`; `apps/web/Dockerfile:45`.

**Oprava:**
1. `pdfjs-dist@5.4.296` deklarovaná priamo v `apps/web/package.json`
   (lockfile aktualizovaný; resolve preukázané).
2. `extractPdfText` — `doc.destroy()` presunutý do `finally`
   (`lib/inventory/pdf-invoice-parser.ts`) — PDF dokument sa už neustratí
   ak extrakcia hodí.
3. Nový unit test `lib/inventory/__tests__/pdf-invoice-parser.test.ts`
   (9 testov): extrakcia minimálneho štruktúrovane platného PDF bufferu
   (xref offsety vypočítané) — overuje celý reťazec pdfjs legacy build +
   fake worker + DOMMatrix polyfill z produkčného `instrumentation.register()`
   v Node; rejection ne-PDF bufferu; AI prompt-injection guardy (viz oblasť 8).

**Dopad:** build už viac nezávisí na tranzitívnej verzií; test dokazuje, že
extrakcia funguje aj mimo webpack (Node runtime — rovnaká cesta ako fake
worker v produkčnom server bundle).

## 2. WhatsApp webhook security

**Zistenie:** Vyhodené body sú bezpečné; multi-tenant routing mal
nedeterministickú "prvá prax vyhráva" správanie.

- **ILIKE injekcia — OK.** `fromWaId` vstupuje do
  `ilike(clients.phone, %${fromWaId.replace("+","")})` po `normalizeE164()`,
  ktorá vráti `+<číslice>` alebo `null` (testovaná v
  `lib/messaging/__tests__/phone.test.ts`) — `%`/`_` wildcards do patterns
  dôjsť nemôžu.
- **Twilio signature vs proxy URL — OK.** `validateTwilioSignature` skúša
  both URL varianty (nextAuth host + public `appBaseUrl`), takže reverse
  proxy s rôznym venovaným hostom nenechá webhook zlyhať na signature.
- **DedupeKey constraint — OK.** `communications.dedupeKey` a
  `extWhatsappMessages.twilioSid` majú GLOBÁLNE unikátne indexe;
  `onConflictDoNothing()` deduplikuje Twilio retry.
- **Multi-tenant routing — MEDIUM (opravené).** Loop cez max 5 zladených
  klientov (rôzne praxe) + globálne unikátne dedupeKey = iba PRVÝ insert sa
  zapíše, ostatné no-op. Ktorá prax vyhrávala záviselo od Postgres row
  orderu (nie je garantovaná). **Oprava:** `orderBy desc(clients.createdAt)`
  → deterministické "najnovší klient vyhráva"
  (`app/api/webhooks/whatsapp/route.ts`). Zmeny v `resend/route.ts` identická
  — tam sa nezasahovalo (mimo 24h scope, značené nižšie).

**Test:** existing webhook E2E + typecheck; determinizmus je garantovaný
SQL orderBy (nové unit testy by vyžadovali mockovanie celého drizzle reťazca
+ Twilio — odporúčané ako follow-up).

## 3. AI inference proxy / ai-config-resolver

**Zistenie:** Tri medzery po migrácii na AT proxy.

1. **Health check nevedel o AT_PROXY_URL — MEDIUM (opravené).**
   `hostedAiCheck()` v `app/api/health/route.ts` skúmal len Vertex OIDC
   env / `ANTHROPIC_API_KEY`. Na proxy-only deployment (predvolený model
   `gemini-3.8-flash` cez AT proxy) by health hlásil AI problem hoci AI
   funguje — a naopak: ak Dokploy deploy vymaže `AT_PROXY_URL` (oblasť 9), health by to nezachytil. **Oprava:** `hasInferenceProxyConfiguration()`
   ako first-class vetva (AT_PROXY_URL nastavený → ok s detailom).
2. **Silent fallback si nespravoval model — MEDIUM (opravené).**
   Auto-fallback v `lib/ai/ai-config-resolver.ts`: ak designovaný provider
   (napr. Gemini) zlyhá decrypt a OpenAI je active, fallback vracal
   `model || DEFAULT_AI_MODEL` — teda **Gemini model id na OpenAI endpoint**
   (404 model not found pri prvom výzve). **Oprava:** model id z
   feature-mapping sa opäť použije len ak designovaný provider = ten
   istý; inak `DEFAULT_AI_MODEL`. Decrypt zlyhanie je `console.warn`
   (observovatelné, nie tiché) — zachované.
3. **Thought-signature cache — OK.**
   `geminiThoughtSignatureCache` (module-level Map v
   `lib/ai/ai-config-resolver.ts`) je omedzený na 500 záznamov s FIFO
   evikciou — žiadny leak; kľúč = tool-call id (per-request).

**gemini-3.8-flash — OK.** Overené na `ai.google.dev` (aktuálny model,
released ~2026-09, default pre Gemini Managed Agents).

**Test:** 3 nové testy v `lib/ai/__tests__/ai-config-resolver.test.ts`
(decrypt-fail fallback bez model leak; preservation modelu na primary
OpenAI; default pri neaktívnych provideroch).

## 4. Voice transcription

**Zistenie:** HIGH — zdieľaný AbortController a chýbajúca fallback pre
ne-Gemini proxy target.

1. **Zdieľaný 60 s timeout na kandidátov modelov** — po timeout/abort
   prvého kandidáta mali ďalší kandidát starnutý aborted signal a odbehli
   hneď (fallback slučka fakticky nefungovala). **Oprava:** každý kandidát
   dostane vlastný `AbortController` napojený na celkový 60 s budget
   (`lib/voice/transcription.ts`).
2. **`image_url` data URL funguje len pre Gemini na proxy.** Ak AT proxy
   smeruje na iný (OpenAI-compatible) model, request format je odmietnutý
   (4xx) a transkripcia padla. **Oprava:** po 4xx sa rovnaký model
   reattemptuje s OpenAI-compatible `input_audio` content partom
   (format odvodený z MIME). 5xx/network chyby idú rovno na ďalší
   kandidát.
3. **Bezlimitný direct input — MEDIUM (opravené).**
   `transcribeAudioDirect` teraz guarduje base64 veľkosť proti
   `MAX_AUDIO_BYTES` (25 MB) — defense in depth pod zod limitom. S3 cesta
   už bola limitovaná (`maxBytes`).

**Test:** existing `transcription.test.ts` (3 testy) — happy path, error
path; fallback logika pokrytá typmi + typecheck (plné fetch matrix testy
odporúčané ako follow-up).

  flat-first runtime sémantikou `getNestedValue`) pred/po = **0

## 8. PDF AI prompt injekcie + validácia

**Zistenie:** MEDIUM-HIGH — surový 8000-char slice PDF textu šiel
priamo do LLM promptu bez delimitácie; AI odpoveď sa validovala len
prítomnosťou `items` pole.

**Oprava** (`lib/inventory/pdf-invoice-parser.ts`):
1. **Sanitizácia:** `sanitizeInvoiceText` odobrá control characters,
   zero-width a bidi-override znaky (nástroje injekcie), zloží nadbytočné
   prázdne riadky.
2. **Untrusted wrapper:** dokument idie do promptu medzi
   `<INVOICE_DOCUMENT>` značky s výslovným príkazom ignorovať náleto
   v texte.
3. **Validácia AI response** (`assertPlausibleAiExtraction`):
   items ≤ 500, `quantity` ≠ 0 a |q| ≤ 10 000, `unitPriceWithoutVat` ≥ 0,
   totals finite a ≤ 10 000 000, meno ≤ 255 znakov. Zlyhanie →
   rule-based fallback (žiadny pol-šibeničný údaj v UI).
4. `quantity: Number(...) || 1` (skryvala 0/NaN) → `|| 0` + explicitný
   rejection.

**Human review step — existuje.** Flow: `parseAttachmentForImport`
(preview s `suggestedAction` + `isControlledSubstance` flags) →
človek → `confirmImport` (max 500 items, explicitný payload).
**Slabosť (opravená):** `applyConfirmedItems` verila client action —
override "skip" na controlled substance sa zapísal do inventory.
**Oprava:** server-side gate v `applyConfirmedItems` (rozdelenie zo
`policy.ts`) → FORBIDDEN pre non-skip action s OPL menom.

**Test:** 9 nových testov v
`lib/inventory/__tests__/pdf-invoice-parser.test.ts` (injection guard
quantity, item cap, non-JSON, untrusted wrapper v odoslanom prompte) +
2 nové testy v `extensions-wholesaler-confirm-import.test.ts`
(server-side OPL gate + skip allowance).

## 9. Dokploy deploy env wipe (známe CRITICAL)

**Zistenie:** Dokploy Compose deploy **prepíše `.env` na serveri** —
109+ premenných sa stratí pri každom deployi. `deploy.ps1` to len
*pripomínal* manuálne (`dokploy env push` ako komentár), hardcoval
webhook URL s tokenom v repozitári, a smoke test nikdy nevrátil non-zero.

**Opravy** (`.agents/skills/deploy/scripts/deploy.ps1`):
1. **Aktívna env ochrana:** pred webhookom sa vždy vykoná
   `dokploy env push .env.production.local`; zlyhanie → **exit 1** (deploy
   zastavený skôr než by sa env vymazali).
2. **Webhook URL:** odstránený hardcode; chýbajúca
   `DOKPLOY_DEPLOY_WEBHOOK_URL` (env / .env) → chybna správa + exit 1
   (token už nie je v repozitári).
3. **Smoke test:** nepriaznivý `/api/health` (ok=false / DB nedostupná)
   → **exit 1** s pokynmi na next steps.

**Zvyšné riziko (CRITICAL, nedá sa z tohto repo vyriešiť):** root cause
žije v Dokploy konfigurácii (env management / .env handling pri Compose
build). Dokploy health endpoint (`vet.dev.significa.sk/api/health`)
nebolo z sandboxu dosiahnuteľné (TLS) — liveness overenie nemožné.
**Odporúčanie:** skúsiť v Dokploy toggling "environment variables" na
"persist across deploys" (alebo použiť Dokploy Secrets), kým sa toto
nenespraví, deploy.ps1 auto-push je jediná ochrana.
