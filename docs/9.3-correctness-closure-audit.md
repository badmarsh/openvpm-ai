## 1. Executive Summary & Audit Scope

This audit reviews all real write paths in `badmarsh/openvpm-ai` involving AI-assisted clinical records, clinician confirmation, audit chain persistence, and agent tool authorization.

Prior sprints introduced the v2 chain columns in `packages/db/schema/ext_ai_audit_log.ts` and created the tamper-evident verifier in `apps/web/lib/ai/audit-chain.ts`. However, rigorous inspection of the production write paths reveals critical architectural gaps:
1. **Unpopulated Chain Fields (Production Audit Severed):** The production router write paths (`voice.ts`, `imaging.ts`, `discharge.ts`) were still executing manual `insert(extAiAuditLog)` calls that left `sequenceNumber`, `actorRole`, `actionType`, `previousEventHash`, and `eventHash` as `NULL`. Every real event created by users was rejected by the verifier as missing required chain fields.
2. **Severed Transaction Boundary in Discharge:** In `discharge.ts`, the discharge report was inserted into the database in one query, followed by a non-transactional audit insert. If audit logging failed, the clinical record remained committed without audit attribution.
3. **No Centralized, Concurrency-Safe Audit Append Service:** Sequence numbers and previous event hashes were not allocated using a database transaction lock. Any concurrent write to the same practice chain would risk sequence collisions or predecessor linkage forks.
4. **Missing Optimistic Concurrency on Clinical Finalization:** Imaging analysis and discharge reports lacked expected revision checks. Competing updates or duplicate submits would silently overwrite clinical findings.
5. **Replay-Vulnerable Clinician Confirmation:** Clinician confirmation was merely a boolean flag (`clinicianConfirmed: true`). It was not bound to actor ID, actor role, practice ID, entity revision, original draft hash, or final payload hash, nor did it carry an expiration or one-time consumption guard.
6. **Incomplete Agent Tool Authorization Inventory:** Only two tools (`create_prescription` and `get_controlled_substances_log`) called `assertAgentRole()`. Other write-capable and sensitive read tools lacked fail-closed role enforcement.

## 3. Detailed Path Analysis & Defect Identification

### 3.1 Voice SOAP Finalization (`apps/web/server/routers/extensions/voice.ts`)
- **Current Behavior:** Clinician calls `saveAsSoapNote` with `clinicianConfirmed: true`. A transaction is opened calling `createFinalizedAppointmentSoapNote` and inserting `extAiAuditLog`.
- **Defects:**
  1. The insert to `extAiAuditLog` supplies only `practiceId`, `actorId`, `actorName`, `entityType`, `entityId`, `originalDraftHash`, `confirmedContentHash`, `wasEditedByClinician`, and `confirmedAt`.
  2. `sequenceNumber`, `actorRole`, `actionType`, `previousEventHash`, `eventHash`, and `canonicalizationVersion` are omitted.
  3. `ctx.db.update(voiceDictations).set({ soapNoteId: note.id })` executes after the transaction commits. If the network or process dies before this update, the dictation remains unlinked while the SOAP note is finalized.
  4. No concurrency guard prevents two simultaneous calls from creating competing notes or race conditions.

### 3.2 Diagnostic Imaging Confirmation (`apps/web/server/routers/extensions/imaging.ts`)
- **Current Behavior:** Clinician calls `confirmAnalysis` with `clinicianConfirmed: true` and `finalReport`.
- **Defects:**
  1. Same omission of v2 audit chain fields.
  2. The update query `where(and(eq(aiImagingAnalyses.id, analysis.id), eq(aiImagingAnalyses.practiceId, ctx.practiceId)))` does NOT assert `status: 'PENDING'` or an expected revision.
  3. If two clinicians or two browser tabs confirm concurrently, both requests pass validation and both execute `UPDATE ... RETURNING`. The second request overwrites the first request's report, and two disjoint audit entries are created.

### 3.3 Discharge Letter Finalization (`apps/web/server/routers/extensions/discharge.ts`)
- **Current Behavior:** Clinician calls `save` with `status: 'finalized'` and `clinicianConfirmed: true`.
- **Defects:**
  1. `ctx.db.insert(dischargeReports)` runs first and commits.
  2. `ctx.db.insert(extAiAuditLog)` runs second in a completely separate query. If it throws (e.g. constraint violation, connection timeout), the finalized discharge report is already permanently saved without an audit record (fail-open audit).
  3. Webhook dispatch (`dispatchWebhookEvent`) and sympathy gate triggers occur immediately without transactional coordination.
  4. Missing v2 chain fields in the audit row.
  5. No mechanism to update an existing draft discharge report with optimistic concurrency.

### 3.4 Agent Tool Authorization Layer (`apps/web/lib/agent/tools.ts`)
- **Current Behavior:** 25 tools exist. Only `create_prescription` and `get_controlled_substances_log` call `assertAgentRole()`.
- **Defects:**
  1. Privileged write tools (`book_appointment`, `record_vital_signs`, `record_vitals_from_speech`) and sensitive clinical/financial read tools (`get_invoice_summary`, `get_lab_results`, `audit_missed_charges`, `generate_rvps_report`, etc.) did not enforce role verification at the tool level.
  2. While tRPC routes have `requireRole()`, invocations originating through agent tool-sets, direct tool callers, or automated pipelines would execute without fail-closed authorization.

## 4. Proposed Remediation Architecture

### 4.1 Phase B — Centralized Atomic Audit Append (`appendAiAuditEvent`)
- Create `apps/web/lib/ai/audit-ledger.ts` providing `appendAiAuditEvent(tx: Database, input: AppendAiAuditEventInput)`.
- Enforce per-practice transactional advisory lock using PostgreSQL:
  `SELECT pg_advisory_xact_lock(hashtextextended('ai_audit_chain:' || practiceId, 0))`
- In the same transaction:
  1. Retrieve highest `sequenceNumber` and `eventHash` for the practice.
  2. Assign `sequenceNumber = maxSeq + 1` (or 1 for genesis).
  3. Assign `previousEventHash = latest.eventHash` (or null for genesis).
  4. Compute deterministic `eventHash` using canonical JSON serialization from `audit-chain.ts`.
  5. Insert the row with full attribution: `actorId`, `actorName`, `actorRole`, `actionType`, `entityType`, `entityId`, `originalDraftHash`, `confirmedContentHash`, `wasEditedByClinician`, `confirmedAt`, `sequenceNumber`, `previousEventHash`, `eventHash`, `canonicalizationVersion`.
- Fail-closed: if audit insertion fails, the entire transaction rolls back.

### 4.2 Phase C — Real Optimistic Concurrency
- Add `revision: integer("revision").notNull().default(0)` to `packages/db/schema/ext_imaging.ts`, `packages/db/schema/ext_discharge.ts`, and `packages/db/schema/ext_voice.ts`.
- All finalization endpoints require `expectedRevision`.
- The UPDATE statements assert `eq(table.revision, input.expectedRevision)` and the expected pre-finalization status (e.g. `status: 'PENDING'` or `status: 'draft'`).
- Return typed `CONFLICT` error with conflict details if the record was modified concurrently.

### 4.3 Phase D — Replay-Safe Clinician Confirmation Envelope
- Create `packages/db/schema/ext_confirmations.ts` defining `ext_clinician_confirmations`.
- Confirmations bind: `confirmationId`, `practiceId`, `actorId`, `actorRole`, `actionType`, `entityType`, `entityId`, `expectedRevision`, `originalDraftHash`, `confirmedContentHash`, `expiresAt`, `status`.
- Provide `apps/web/lib/ai/clinician-confirmation.ts`:
  - `issueClinicianConfirmation(...)`: Issues a time-limited (15-minute) one-time confirmation token.
  - `consumeClinicianConfirmation(tx, ...)`: Atomically validates all bindings and sets `status = 'CONSUMED'` within the finalization transaction.
  - Fail-closed validation for expired, consumed, altered payload, altered draft, role mismatch, actor mismatch, and practice mismatch.

### 4.4 Phase E — Agent Tool Security Matrix & Enforcement
- Audit all 25 tools in `apps/web/lib/agent/tools.ts`.
- Implement fail-closed `assertAgentRole()` across all write and sensitive read tools.
- Document permissions in `docs/agent-tool-security-matrix.md`.

## 5. Test Matrix & Verification Strategy

1. **Unit Tests:**
   - Audit ledger: canonicalization, hashing, genesis event, sequence chaining.
   - Confirmation envelope: expiration, double consumption, actor/role/practice/entity/action/payload/draft tampering.
   - Agent tool authorization: deny undefined, null, empty, whitespace, unknown, and insufficient roles across all sensitive tools.
2. **Integration Tests:**
   - Voice SOAP finalization with transactional audit and v2 chain verification.
   - Imaging confirmation with real optimistic concurrency (two concurrent requests: exactly one wins, one conflicts).
   - Discharge report finalization in single transaction with external side-effect isolation.
   - Audit verifier running against actual database-inserted rows.
3. **E2E Pilot Flow:**
   - Synthetic end-to-end clinical workflow: reception check-in -> encounter -> voice SOAP draft -> clinician finalization -> audit chain verification -> prescription -> billing -> discharge finalization -> portal safe projection -> RBAC boundary rejection.

## 6. Migration & Deployment Impact

- **Database Schemas:**
  - New table: `ext_clinician_confirmations` in `packages/db/schema/ext_confirmations.ts`.
  - Additional columns in existing extension tables:
    - `packages/db/schema/ext_imaging.ts`: `revision` (integer, default 0).
    - `packages/db/schema/ext_discharge.ts`: `revision` (integer, default 0).
    - `packages/db/schema/ext_voice.ts`: `revision` (integer, default 0).
- **Migration Strategy:** Applied via `pnpm db:push` in alignment with SKILL.md. All added columns have safe defaults (`default(0)`), ensuring zero-downtime and non-destructive backfill for existing rows.
- **Upstream Sync Guarantee:** All modified and new schemas reside exclusively in `packages/db/schema/ext_*.ts`. No vanilla schema files in `packages/db/schema/*.ts` are touched.
